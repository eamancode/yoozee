# M6 设计：短剧流程与技能解耦

目标：把变化快慢不同的两部分分开。流程（步骤、顺序、界面、步骤间交接的数据契约）变得慢，改了要发版。技能（每一步怎么想、怎么写）变得快，管理员从本地仓库构建出包，上传后自动校验和评测，通过就启用，不用发版。

## 0. 已确认的需求

| 问题 | 结论 |
| --- | --- |
| 谁管理技能包 | 只有管理员；高级用户暂不考虑 |
| 技能覆盖哪些步骤 | 只管调文本模型写内容的步骤。视频提示词编译和出图模板维持现状（编译档案、提示词模板） |
| 某一步用哪个包 | 按项目的风格档案固定绑定，用户不用选 |
| 风格档案从哪里来 | 新建项目时显式选择，5 选 1，默认按画风推荐，用户可以改 |
| 技能的源头 | 本地仓库 yoozee-skills（git）为准，线上只启用和回退，不在线编辑 |
| 版本跟随 | 所有项目自动用最新启用的版本 |
| 启用关卡 | 先做静态校验，再在评测集上真跑一遍；通过就自动启用 |

## 1. 三个概念

### 1.1 步骤：代码定义，改了要发版

代码里有一张步骤表，每个步骤写明下列内容：

| 字段 | 含义 |
| --- | --- |
| `id` | 例如 `chapter.assets`（提取资产）、`chapter.shots`（生成分段）；以后加 `episode.story`、`episode.script` |
| `contract` | 输出契约：仓库里的 JSON Schema 文件，带版本号，例如 `chapter.shots@2` |
| `inputs` | 代码负责组装的变量：章节正文、项目画风、已确认角色外观、资产清单与锚点、每集时长 |
| `parser` / `checks` | 解析器和检查器，例如 Go 版的 check shots 和装段 |
| `budget` | 技能上下文的字数上限，例如 32k |

**输出契约的文字由代码按 schema 生成，不再手写在前端。** 现在 `storyboardRowsOutputContract` 是手写字段清单，再靠技能用 outputFields 补上 spec，两头各知道一半。改成按 schema 生成以后，契约只有一份。

### 1.2 技能包：本地写好、上传生效

技能包就是现在的技能目录（SKILL.md 加知识卡），多一份清单文件 `package.json`：

```json
{
  "id": "yz-chapter-shots",
  "step": "chapter.shots",
  "contract": "chapter.shots@2",
  "profiles": ["live-realism", "duanju-shiga"],
  "version": "2.3.0",
  "files": ["SKILL.md", "cards/相机四维编码.md", "cards/镜头表规则速查.md", "cards/情绪弧索引.md"],
  "eval": ["qichuang-e01", "xuanyi-e01"]
}
```

- 一个包只服务一个步骤，可以覆盖多个风格档案。
- 包里不写契约，契约由步骤提供，包只声明自己满足哪个契约版本。
- 打斗、悬疑等题材的差异，用不同的包或包里的不同知识卡来体现，不需要改流程。

### 1.3 绑定：风格档案决定用哪个包

绑定是一张「风格档案 × 步骤 → 技能包」的表，由管理员在后台设置，每格一个包。运行时先查项目的风格档案，再查这张表，取到包后用它当前启用的版本。表里没配的格子用该步骤的默认包。

## 2. 一次完整的更新：从本地到线上

1. **本地编写与自测**：在 yoozee-skills 里改技能，用 Claude Code 和本地工具（check.py、pack.py）跑自己的样例。
2. **构建**：`python build.py --package yz-chapter-shots` 生成 zip，里面有清单文件、所有文件和内容哈希，并在本地先做一遍静态校验。
3. **上传**：在后台「流程技能」页上传 zip，或者用 CLI 带管理员令牌上传。以后可以加一个 GitHub Action：仓库打 `skills-v*` 标签时自动构建并上传，这样「本地仓库为准」就由流程保证，不靠人记。
4. **静态校验**（秒级），以下任一不过，就标记「未通过」并说明原因：
   - 清单文件格式正确；`step` 存在。
   - `contract` 和线上代码中这一步的契约版本一致。
   - `files` 都在包里，SKILL.md 点名必读的卡都在 `files` 里。
   - 注入的总字数不超过这一步的上限。
   - `profiles` 都是已知的风格档案。
5. **真跑评测**（约 5 分钟，花少量文本积分）：
   - 对 `eval` 列出的评测章节，用线上默认文本模型和这个包真跑这一步。
   - 结果交给真实的解析器和检查器处理。
   - 再跟当前启用的版本在同一组章节上的最近一次结果比较。
6. **自动启用的门槛**：每个步骤一组，写在代码里。`chapter.shots` 的门槛如下：

| 指标 | 门槛 |
| --- | --- |
| 解析成功率 | 100% |
| spec 写出率 | 100% |
| 台词逐字覆盖 | 100% |
| 检查 error | 0 |
| 检查 warn | 不超过当前版本的 120% |
| 估时合计 | 不超过每集时长的 1.1 倍 |
| 截断 | 0 |

全部达标就自动启用并记一条日志。不达标就保持「未通过」，后台显示指标对比和逐章差异。管理员可以手动强制启用，必须写明原因。

7. **回退**：后台每个包都列出历史版本，点一下就能启用任一历史版本。版本号和内容哈希都写进每个任务记录，出问题能定位到是哪一版生成的。

## 3. 用户看到的变化

- **新建项目表单**：新增「风格档案」，5 选 1，默认按所选画风推荐（用第三期的对照表），用户可以改。项目设置里也能改。
- **提取资产、生成分段弹窗**：不再让用户选技能，改为显示「本步使用：章节分镜 v2.3.0（真人剧）」。
- **分镜制作页**：每段显示是由哪个技能版本生成的。
- **技能库**：保留给画布和 Agent 用，和短剧流程的技能包分开；内置的 yz-chapter-shots 从技能库中撤下，改由流程技能管理。

## 4. 后端改动（一次发版）

| 改动 | 说明 |
| --- | --- |
| 步骤表 | `internal/drama/steps.go`：`chapter.assets`、`chapter.shots` 两个步骤及其契约 schema、变量组装、解析器、检查器、启用门槛 |
| 契约生成 | 按 schema 生成契约文字，替换前端手写的 `storyboardRowsOutputContract` |
| 数据 | 复用 `skills` / `skill_versions`（#12 已有 `origin`、`builtin_version_id`），新增来源 `package`。新表 `drama_step_bindings`（风格档案、步骤、技能 ID）。`drama_eval_runs` 扩展 `stage` 为步骤 ID，并记录门槛结论。项目新增 `style_profile` 字段 |
| 接口 | `POST /api/admin/drama/packages`（上传）、`GET .../packages/:id/versions`、`POST .../versions/:vid/activate`、`GET/PUT /api/admin/drama/step-bindings`；评测改为异步任务，结果写进 `drama_eval_runs` |
| 运行时 | 生成分段、提取资产在服务端按项目档案解析绑定、组装提示词（技能内容 + 代码变量 + 契约），前端只发「对这一章跑这一步」，不再拼提示词 |
| 后台页面 | 「流程技能」：绑定矩阵、上传、版本列表（状态、门槛结果、启用、回退）、评测报告 |
| 迁移 | 现有 `yz-chapter-shots` 作为第一个包导入；提取资产的提示词模板 `chapter_assets_extract` 转成第二个包 `yz-chapter-assets`；内置技能目录里的这两份删除 |

## 5. 契约变更怎么发版

改契约就是改流程，必须发版：

1. 先在本地把对应的包升级到新契约，构建好。
2. 发版时契约版本号加一，例如 `chapter.shots@3`。旧包因为契约版本不符，自动标记为「不兼容」。
3. 部署后立刻上传新包，静态校验和评测通过后自动启用。
4. 从部署到新包启用之间，这一步会提示「技能包与流程版本不符」，不让运行。

不做兼容层，这符合 AGENTS.md 的规定。所以发版清单里要写明「先上传新包」。

## 6. 分期

| 期 | 内容 | 验收 |
| --- | --- | --- |
| 一 | 步骤表、契约按 schema 生成、服务端组装提示词；生成分段改成按项目档案绑定，去掉弹窗里的技能选择；新建项目选档案 | 测试项目生成分段的提示词与现在一致，只是来源变成绑定；指标不变 |
| 二 | 包格式、`build.py --package`、上传、静态校验、版本列表、手动启用和回退 | 本地改一个字、上传，后台出现新版本，手动启用后生成的提示词带上这处改动；回退后恢复 |
| 三 | 真跑评测和自动启用门槛；评测集按风格档案配置（真人剧用《七床》E01，其他档案用四类题材测试章节） | 故意上传一个坏包（缺 spec 说明），被门槛挡下；上传一个正常的小改动，自动启用 |
| 四 | 提取资产迁成包；可选 GitHub Action 打标签自动上传 | 提取资产走绑定，质量指标不降 |

## 7. 不做

- 不让高级用户上传或替换包。
- 视频提示词编译继续用编译档案，出图继续用提示词模板，不并入技能包。
- 不在线编辑技能内容；线上只能上传、启用、回退。
- 不为旧任务、旧版本做兼容。
