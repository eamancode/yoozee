### 3. CL 色彩光影设计卡与 ST 的关系

`CL` 不是单独的一句“电影级光影”，而是 `ST` 的光影执行层。`ST` 规定项目像什么，`CL` 规定当前项目或场景如何打光。角色图、场景图和 06 视频提示词都必须把 `CL` 翻译成当前可见光源、光线方向、亮暗区域、色温、反差和禁止项。

如果 `ST/CL` 风格光影与当前场景真实光源冲突，按以下优先级处理：

```text
当前场景真实光源和剧情时段优先；
项目风格的画面质感、反差、颗粒/线条/渲染媒介保留；
NP 风格防跑偏负面词保留；
不要机械输出两套互相冲突的光影。
```

示例：

```text
港风医院冷白灯：医院走廊顶部冷白荧光灯作为主光，人物脸部受光偏冷，但仍保持港风写实的强明暗反差、现实剧集质感和轻微胶片颗粒；禁止韩剧式冷白精修、禁止过度磨皮。
```

## 柚子流程接入说明（输出格式以契约为准）

这一段是柚子接入时追加的，只说明输入和输出格式，不改上面的色彩光影规则和色卡提示词卡的色板设计规则。

- 在柚子「场次色卡」里，项目风格已经在建项目时锁定：输入是锁定的全局风格锚（相当于 `ST` 与 `CL` 的结论）、主基调色卡（按主角组、配角组、道具组、环境组分组的全片底色），以及整部剧的剧集场次表（每场的场编号、场次头、内外 / 地点 / 时间和开头一段正文）、风格档案；不再向用户询问风格，也不改风格锚。没有剧集时给的是原文章节，一章当一集。
- 每一场写一份色彩脚本，落成这一场的场次色卡。写色彩脚本前必须先读取 `cards/色卡提示词卡-色板设计.md`（【用途】【色板设计】【视觉影视参考预案】三段的要求）：【用途】写进 purpose，【色板设计】的跨段共享色 / 场景基础色写进 shared_colors、本段新增色 / 本场关键色写进 new_colors，承接上一场色卡时写 inherits_from，【视觉影视参考预案】写进 references。
- 上面 `CL` 的优先级照用：这一场的真实光源和剧情时段优先，项目风格的质感和禁用项保留。角色、道具的颜色从主基调色卡对应分组里取，同名颜色 HEX 照抄；场景颜色以环境组为基础按本场改。每个颜色写中文名、英文名（name_en）、HEX、用途和 group（归主基调色卡的哪一组）。
- 色卡图由柚子按色值自动合成（色块 + HEX + 中英文色名），不用写出图提示词。
- 输出格式以提示词最后的【受保护输出契约】为准：每场一行色彩脚本（scene 写场编号），不写风格锚、不写 Markdown 卡片和解释文字。
