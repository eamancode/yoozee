# 短剧工作流素材库历史资产复用需求说明

状态：用户已授权 P0、P1 开发与验收；实现、测试及上线结果以本次交付报告为准。

## 1. 需求复述与目标

用户已经上传或生成过的素材，应能在短剧项目中直接选择使用。人物主卡、人物子卡、场景、道具需要替换图片时，可以从自己的素材库选择已有图片；项目需要引用素材时，可以引用已有资产。不能因为图片不在当前浏览器缓存、来自历史项目或位于其他分页，就显示“此素材不适用于当前操作”。

核心目标是打通“查找已有素材 → 预览并选择 → 绑定或引用 → 保存后继续制作”，复用原有文件和资源，不要求重新上传、重新生成或重新提取资产。

本次方案沿用现有素材库、选择弹窗、资源服务和资产版本机制。两条流水线采用相同的素材复用规则，不修改资产提取技能、模型调度、声音流程、视频时长适配或同场景连续生成链。

## 2. 排查结论与证据

### 2.1 已在线上复现的现象

在独立的随行鲜验收项目中，通过“人物主卡预览 → 替换图片”进入“绑定图片”弹窗：

- 顶部显示 443 个素材，当前页展示 40 张图片。
- 当前页 40 张图片均被禁用，提示“此素材不适用于当前操作”，确认按钮不可用。
- 左侧“全部素材”显示 40，与顶部总数 443 的统计范围不同。
- 本次只打开、观察、截图和取消，没有确认绑定、修改原资产或发起模型任务。

用户截图中的 1197 个素材和本次验收账号实际显示的 443 个素材属于不同现场，不据此推断所有历史素材都损坏。本次没有逐一检查用户截图内原始文件的有效性。

### 2.2 根因：服务器分页数据与本地缓存选择合同未打通

| 问题 | 代码事实 | 影响 |
| --- | --- | --- |
| 远端素材被当成本地白名单校验 | `asset-library-picker-modal.tsx:649` 的 `remoteAssetToPickerItem`：远端素材未出现在调用方的本地 `items` 且 `acceptRemoteItems` 为假时，直接设置“不适用” | 图片能展示，但无法选择；是否可用错误地依赖本地缓存 |
| 人物绑定入口没有接入远端选择结果 | `assets.tsx:651` 的图片选择器只在 `imageAsset.visual` 存在时开启 `acceptRemoteItems`；人物使用 `character` 分支，条件不成立 | 人物主卡的历史图片大量误禁用；场景、道具的对应分支已接入远端条目，不能笼统判定全部入口相同 |
| 人物确认绑定仍只查本地数据 | `assets.tsx:481` 的 `bindImagesMutation` 只从本地 store 或插件来源查找图片，未消费弹窗返回的远端 `pickedItems` | 只放开置灰仍不够，确认时会报“请选择一张完整的角色设定图”等错误 |
| 项目“引用素材”存在同类接入缺口 | `assets.tsx:300` 的 `addMutation` 从 `availablePickerItems` 或本地 store 查找；其选择器未开启远端条目接收，也未把 `pickedItems` 传给引用流程 | 远端历史素材也可能无法加入项目；这是代码确认的缺口，本次未实际提交引用 |
| 类型筛选后的分类计数只算当前页 | `asset-library-picker-modal.tsx:414` 在存在 `remoteKind` 时不采用服务端分类计数，回退统计当前页 | 绑定图片时出现“全部素材 40 / 共 443”之类的混淆 |
| 人物子卡缺少素材库复用入口 | `project-character-variants.tsx:55` 已支持上传并替换为新版本，但当前子卡操作没有对应的素材库选择入口 | 需要从历史素材复用子卡图片时，只能绕行重新上传；这属于入口补齐，区别于主卡误禁用 bug |

现有框架具备所需能力：选择弹窗已经返回 `ids` 和 `pickedItems`，并保存跨页选中条目；`studio/cast-library-picker.tsx:78` 已示范远端条目接收、图片资源解析及直接复用。优先修复工作台调用方的接入，不能为此重写素材库或全量加载历史记录。

### 2.3 另外需要明确的资产与图片边界

当前人物绑定入口限定 `remoteKind="image"`，共用选择器默认还排除实体角色卡。因此，“一张图片素材”和“带有形象图的角色资产卡”不是同一种候选，后者不会自动作为可绑定图片出现。

本需求同时明确：已有角色卡带可用形象图时，允许取其图片来复用，但必须让用户知道使用的是图片，不是导入另一人物的全部设定。没有图片的角色卡不能凭缩略图或标题伪造图片资源。场景、道具同样只能复用实际存在的图片。

## 3. 范围与优先级

| 优先级 | 范围 | 交付目标 |
| --- | --- | --- |
| P0 | 人物主卡“绑定图片” | 远端图片可选；提交消费完整选中条目；真实资源绑定成功并刷新显示 |
| P0 | 项目“引用素材” | 使用远端资产记录建立项目引用，支持历史上传和生成素材，避免重复引用 |
| P0 | 资源解析与失败反馈 | 正确区分资产 ID 和资源 ID；保存失败保留旧图，不显示虚假成功 |
| P1 | 人物子卡素材库选择 | 增加“从素材库选择”，保留已有上传入口，按子卡图片角色保存新版本 |
| P1 | 带图资产卡复用 | 人物支持选择已有角色卡的可用形象；场景、道具支持其可用图片，明确预览与来源 |
| P1 | 交互与一致性 | 计数口径、具体禁用原因、跨页选择、图片预览，以及场景/道具入口回归 |

“绑定图片”以单张选择为主；“引用素材”沿用现有多选能力。音频、视频、文本作为项目素材引用时，保留当前支持范围并回归，不能因本次图片修复而被误拦截。本次不扩展声音绑定业务或重做声音流程。

## 4. 功能需求

### 4.1 可用素材判定

1. 当前用户有权使用、资源存在且就绪的图片可以选择，与上传或生成来源、创建时间、原项目、页码、本机缓存命中情况无关。
2. 图片的业务分类用于查找，不作为绑定图片的硬门槛。例如一张被归入“素材”或“其他”的人物图片，仍可由用户选作人物形象。
3. 主卡可以选择已有四宫格、三视图或其他人物图片。提示推荐规格并提供预览，不增加图像识别或人工审批，不因系统无法识别宫格数量而阻止手动绑定。
4. 图片绑定弹窗默认筛选可用图片及支持取图的资产卡，音频、视频等不适用类型不混入图片列表。
5. 回收站素材、资源未就绪、资源不存在、无实际图片的资产卡应显示具体原因；回收站素材先通过已有恢复操作恢复，再选择。
6. 只有本机文件、尚未上传完成的素材，复用已有上传能力完成持久化后再绑定。上传失败应明确提示，不能把本地缓存成功当作服务器保存成功。
7. 不得以“尚未缓存”作为不可用原因，也不得要求用户先逐个打开旧素材来预热缓存。

### 4.2 人物主卡与子卡绑定

1. 主卡保留现有“更换 / 替换图片”入口；子卡在现有上传入口旁增加“从素材库选择”。
2. 进入选择器时显示绑定目标名称，并明确操作是替换该卡图片。
3. 选中图片后可预览，确认按钮显示“绑定图片并保存新版本”，避免把“新版本”误解为重新调用图片模型。
4. 提交时复用选中图片的实际资源 ID；已在服务器的图片无需再次上传。
5. 主卡与子卡沿用各自现有 representation 角色规则，不为两条流水线新增重复资产结构。
6. 仅更新目标卡图片版本及图片来源记录，保留角色名称、身份、外貌文字、声音绑定、主子卡关系、子卡服装/状态、关联场次等已有业务信息。
7. 人物主卡换图不自动批量重生成或覆盖子卡，子卡换图不替换主卡及其他子卡。
8. 取另一角色卡的图片时，必须仅复用该图片，不导入原角色设定或声音。
9. 保存成功后刷新主卡/子卡缩略图、预览和当前版本；刷新页面仍显示已绑定图片。

### 4.3 场景与道具绑定

1. 保留已有“绑定图片”入口，采用与人物相同的远端素材选择和资源解析规则。
2. 保存为目标资产新版本，保留资产定义、场次关联、主从关系等原信息。
3. 复用微缩场景图、道具参考图时保持原图，不自动裁切、重绘或转换成另一类产物。
4. 保留已有 `expectedVersionId` 并发校验；目标版本已变化时提示刷新后再选，不覆盖更新后的内容。

### 4.4 项目引用素材

1. 搜索、分类和分页均查询用户有权使用的素材，选中远端条目即可引用到当前项目或指定文件夹。
2. 复用素材原有资产 ID 和资源，不复制文件、不把已有生成结果重新提交生成。
3. 已引用素材显示“已在当前项目”，不可因本地缺失而再次建立重复引用；重复请求也不增加重复项目引用。
4. 多选允许跨页、跨搜索保留选择；只提交用户选中的条目，不把返回的整个候选列表加入项目。
5. 批量引用部分失败时，列出失败条目及原因，保留失败选择供用户处理，不能以全部成功提示掩盖部分失败。
6. 业务分类与特殊资产类型继续由服务端校验，不把普通图片自动升级为系统生成的“分镜参考”或“色卡”。

### 4.5 带图资产卡取图

1. 素材库中的图片素材直接使用其图片资源；角色卡使用当前有效形象资源。
2. 场景、道具等资产带图片时，读取该资产当前有效版本的图片，不用资产 ID 充当资源 ID。
3. 一个资产存在多张可用表示时，优先使用当前主图，并允许在预览中选择已有表示；不能静默选到旧版本或非图片资源。
4. 无法解析图片时提示“该资产暂无可用图片”，不显示通用“不适用”。
5. 服务器查询若暂不支持按可复用图片筛选，只补充必要的候选查询和计数能力，保持分页，不将整个素材库下载到浏览器后过滤。

### 4.6 交互反馈

- 顶部显示“共 N 个匹配素材 · 已选 M 个”，分页区显示当前页范围。
- 左侧“全部”和分类数量采用与列表相同的权限、状态、关键词及媒体类型口径，统计全部匹配记录，不统计当前 40 项冒充总数。
- 可用图片正常显示缩略图与选择状态；不可用项显示具体原因，例如“图片尚未上传完成”“该角色卡没有形象图”。
- 图片预览与选中操作可区分；键盘可选择、关闭和确认，禁用原因可被辅助技术读取。
- 翻页或搜索加载时明确显示加载状态，不把短暂的空缓存误报为“没有素材”或全部不可用。
- 保存期间禁用重复确认；失败留在弹窗，保留选择并显示错误；成功后关闭并刷新目标内容。
- 取消弹窗不改变图片、不新增版本、不发起模型生成。

## 5. 最小改动方案与职责

| 层次 | 需要做的事 | 边界 |
| --- | --- | --- |
| 共用选择器 | 继续返回选中 ID 与包含远端记录的条目；修正类型过滤后的计数与原因展示 | 不全局无条件放开所有调用方；未能处理远端条目的调用方必须先接入 |
| 工作台页面 | 人物绑定、项目引用消费实际 `pickedItems`，子卡复用同一图片选择能力 | 页面协调目标和反馈，不自行拼模型生成协议 |
| 资源解析服务/helper | 解析图片素材、带图资产及必要的本机上传结果；复用或提取已有设定页逻辑 | helper 必须隔离实际资源协议，不能只为转发参数新建一层 |
| 现有业务 API | 复用人物 representations、资产图片绑定及项目素材引用接口 | 保留资源归属、就绪状态、项目权限、版本及特殊类型校验 |
| 素材列表 API | 必要时补充可取图候选及同口径分类计数 | 查询在服务端分页，不通过补齐全部本地 store 解决 |

完整提交顺序：读取本次选中条目 → 解析资产与图片资源 → 必要时完成已有文件上传 → 调用目标绑定/引用 API → 等待服务器成功 → 刷新目标与列表。

人物现有 representations 接口没有 `expectedVersionId` 字段，不在文档中冒充已有并发保护。本次先防止重复点击造成重复提交；如实现需要新增并发字段，应同步更新前后端合同及对应测试，不为此次修复扩建通用版本系统。

不存在“先全量同步所有历史素材到本地，才能绑定”的前置步骤；也不以清缓存、迁移业务数据或重生成资产作为常规解决方案。

## 6. 保存、权限与失败规则

1. 服务端始终校验当前用户、目标项目/资产及源资源归属，前端放开选择不能替代服务端校验。
2. 绑定成功创建目标资产新版本；源素材和旧版本不被覆盖或删除。
3. 选中后素材被删除、移入回收站、资源不可用或目标版本变化时，返回可理解的错误，保持原图。
4. 发生上传或绑定失败时不自动反复提交；由用户主动处理或重试本次操作。不得自动重试历史失败任务。
5. 原服务器资源直接复用；对于真正只有本机文件的素材，等待上传完成后再继续，不持久化失效的临时预览 URL。
6. 正常引用与换图不调用文本、图片或视频模型，不产生模型生成任务。

## 7. 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 素材只在服务器存在，本机 store 无此记录 | 图片可选并绑定成功，无“尚未缓存”拦截 |
| A02 | 复用历史手动上传图片 | 使用已有资源，刷新后仍显示正确图片 |
| A03 | 复用历史模型生成图片 | 与上传图片一致，不重新调用模型 |
| A04 | 复用同一用户其他项目的可用图片 | 正常绑定，源项目与源素材不被改动 |
| A05 | 从第二页或搜索结果选择远端图片 | 确认时仍能找到完整条目及资源，不报“请选择图片” |
| A06 | 图片分类为“素材/其他”，绑定人物主卡 | 允许手动选择，不按业务分类误禁用 |
| A07 | 人物主卡保存新图 | 仅目标图片更新，人物设定、声音及子卡保留 |
| A08 | 人物子卡从素材库换图 | 仅该子卡更新，主卡、其他子卡及场次绑定保留 |
| A09 | 选择已有角色卡的当前形象 | 引用正确图片，不复制身份、声音或完整角色卡 |
| A10 | 场景、道具换图；两条流水线分别执行 | 保存版本、缩略图和预览一致，不重绘原图 |
| A11 | 资产 ID 与图片资源 ID 不相等 | 提交实际资源 ID，绑定正确文件 |
| A12 | 项目跨页多选引用 | 仅选中素材加入指定目录，刷新后存在且不重复 |
| A13 | 素材已在当前项目 | 明确显示已引用，重复操作不增加重复引用 |
| A14 | 图片筛选下总数超过一页 | 总数、分类计数和分页使用同一全量匹配口径 |
| A15 | 本机图片尚未上传 | 成功上传后绑定；上传失败保留旧图及当前选择 |
| A16 | 无图角色卡、未就绪/丢失资源、回收站素材 | 显示具体原因，不绕过服务端校验 |
| A17 | 无权访问其他用户资源 | 拒绝绑定，原图不变；不暴露其他用户素材 |
| A18 | 双击确认、网络失败、取消操作 | 无并发重复提交；失败不假成功；取消不写入 |
| A19 | 场景/道具目标版本已变化 | 原版本校验继续生效，提示刷新后处理 |
| A20 | 视频、音频、文本的既有项目引用 | 原有能力不退化，不混入图片绑定候选 |
| A21 | 全部复用与换图操作 | 不新增模型生成任务，不重试历史任务 |

## 8. 开发后验证安排

优先做最小充分验证，不额外跑与此需求无关的技能标准评测：

1. 前端专项：覆盖未缓存远端条目、主卡与子卡选中结果解析、跨页选择、图片资源解析、重复确认、部分失败及计数。
2. 接口回归：复用现有绑定与项目引用测试，检查资源归属、就绪状态、保存后新版本及错误保留旧图；有接口或字段变化再补对应集成测试。
3. 真实前端：用隔离验收项目分别选择已有上传图和生成图，覆盖两条流水线的人物主卡、子卡、场景、道具及项目引用，保存并刷新验证。使用独立空缓存测试环境或受控 mock，不清理用户现有浏览器数据。
4. 根据实际改动运行前端 build；只有涉及后端实现时才补相应后端测试。通过后再进入用户授权的发布流程。

排查阶段已完成代码调用链检查与线上只读复现；开发阶段按上述范围执行，不将排查截图作为修复通过证据。
