## 3. 新技能要点（决定了集成方式）

- 结构：`SKILL.md`（契约与路由）＋ `params.md`（P01–P64）＋ `stages/S0–S8` ＋ `templates/` ＋ `examples/` ＋ `prompts/` ＋ `tests/` ＋ `dist/`（对话单文件版）＋ `archive/`（约 3.4 MB 知识库，**生成时不读取**）。

- 交付物：每个「单元」一张卡 = 【导演分镜卡】＋【粘贴提示词】；一个单元 = 一次视频生成；外加世界圣经卡（不变量）与集交接卡（跨集状态）。
- 硬约束：单元 ≤30 秒（含 1 秒站位交接镜头）、提示词 ≤15000 字符、参考图 ≤30 张、默认无背景音乐、不向用户提问而是给"导演提案"进待确认清单。
- 运行时正文（SKILL＋params＋stages＋templates＋examples）约 13.6 万字节、约 5 万字，超过现有单轮 32k 字的步骤预算；按环节装载时每轮约 1–1.5 万字，在预算内。**必须分环节多轮调用，不得截断技能文本。**

### FR3 新流水线一的环节编排
- 与原流水线一相同：拆剧本、导演定画风、场次色卡、资产提取与出图（`yz-assets-integrated`、四宫格、空间母版）、装段、出视频（停靠等人确认花费）、剪辑。

### FR4 本体论导演分镜运行时
- 回合路由按技能 D001：项目首次进入分镜且无世界圣经卡 → 立项回合；之后每集 → 每集回合；用户对某单元提交症状 → 返修回合。
- 分环节调用：每轮装载 `SKILL.md`＋`params.md`＋本环节 `stages/Sx`＋本环节需要的模板；上一轮产物作为下一轮输入。S2–S7 可按需合并调用，但每轮上下文不得截断，且留足输出空间。
- 材料包按 `templates/01_材料包.md` 由系统自动组装：片种、画幅、媒介轨、每集时长取项目设置与风格锁；素材清单 `@图N` 取资产提取与出图的真实结果；世界圣经卡、上集交接卡取 FR5 的持久化数据。
- 平台硬约束优先：P01 单元时长上限取 `min(30 秒, 所选视频模型单段上限)`，作为参数覆盖传入，保证技能产出的单元能直接装段。
- 长输出：服务端按环节和单元分轮（每个单元一轮），每轮输出受控，要求一次写完；模型若仍输出「未完，回复继续」标记，按不合格重试，不做跨回复拼接（实现时由原"自动续写"方案调整，见 R2 审查）。一集最多 16 个单元，每轮输入超过 15 万字直接失败、不截断。
- 续跑：从中断处继续时，技能版本和输入（剧本、素材清单、圣经卡、上一集交接卡、画风）必须与原任务一致，否则拒绝；轮数按实际进度定，只有各轮都写完才只收尾。
- 任务走现有文本任务、SSE、计费、取消和超时机制；单轮超时与总超时可配置。

### FR5 世界圣经卡与集交接卡
- 世界圣经卡项目级持久化，可在项目内查看、编辑；编辑后只影响之后生成的集。
- 集交接卡按集（unit）持久化，第 N 集自动读取第 N−1 集交接卡。
- 待确认清单按集保存并在 UI 中展示。

### FR6 输出解析与装段
- 解析每集七部分；缺任一固定标题即判失败并给出原因，不静默兜底。
- 每张单元卡 → 一个剧情段：段时长取单元总时长；段视频提示词 = 【粘贴提示词】原文，不经现有方言编译器改写（若必须拼接系统字段，需证明不破坏 R3 不变量与 R5 独立可用）。
- 粘贴提示词里的 `@图N` 与段参考媒体一一对应（顺序、数量与材料包一致），超过渠道参考上限时报错而非静默丢弃。
- 【导演分镜卡】里的镜头写入镜头表，供制作台查看；镜头数、时长与单元卡标题一致。
- 台词对照表、节奏总表、讲戏本作为本集产物可查看。

### FR7 质检与返修
