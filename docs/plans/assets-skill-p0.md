# 资产提取技能 P0 增量合并与验收

## 变更边界

`yz-assets-extract` 从已安装的 1.0.0 及仓库 1.1.0 适配尾段增量升级为 1.2.0，保留附件 `character-analyzer` v1.3.0 的原人物、道具、场景分析正文。生产优先规则明确自动步骤使用 JSON Lines，三份设计文档只作为内部分析维度。技能库仍使用同一 ID、五个风格档案和 `assets.extract@1`，不新增数据表、接口或不被解析器接收的字段。

| P0 事项 | 与线上功能的对应关系 |
| --- | --- |
| 剧情关键小道具和产品外观保护 | 角色、场景、道具三类资产，不因饰品或体积小漏掉识别线索 |
| 稳定名称与唯一别名 | 与 `CheckAssetsExtract` 按分类、名称、别名合并的规则匹配，降低不同杯子误合并风险 |
| 先通读后逐场，主卡与临时状态分离 | 角色主卡及 costume/state 子卡，子卡按当前运行场次绑定 |
| 中文外观 600 / 英文 1200 字符 | 对齐解析器实际长度限制，关键细节提前，减少截断损失 |
| 原文颜色优先、补全取锁定色卡 | 主基调和场次色卡继续由后端注入，不让美学推导覆盖原文明示产品颜色 |
| 三视图、无人场景、独立道具 | 与现有资产出图用途对应；场景机位建议不覆盖分镜和视频链规则 |
| 复用场景仍输出一行 | 同步后端首次及续场指令；每轮至少一行，收尾合并不重复建卡或覆盖外观 |
| 出镜说话角色及合并场覆盖 | 编号配角不能用泛称误合并；续场指令带入本轮完整正文及原始场次标题，明确换装落入对应子卡；出场清单按本轮，首次稳定外观按全文汇总 |

## 验收方法

使用用户提供的随行鲜完整 8 场剧本及测试项目已保存的风格锚、主基调和场次色卡。当前切场器将原第 4、5 场同地点同时间合为一场，因此运行 7 轮，原文内容完整保留。

- A：从生产已启用包读取的 1.0.0；B：本次 1.2.0。
- 两组从空资产清单开始，使用同一模型及同一组生产 `assetsExtractPlan` / `AssetsExtractTurnPlan` / `AssetsExtractTurnPrompt` 组装输入。
- 每轮带本组之前的 user/assistant 对话历史，每组内部按场次顺序执行；最终两组并行，从输入完全相同的首轮检查点恢复，第二至第七轮使用最终后端续场指令。首轮提示词逐字及 SHA-256 核验一致，不重复提交已有任务，不混用两组资产或结果。
- 验收通过普通 `canvas_text` 任务，仅保存文本；不带项目资产流水线元数据，不排图片或视频任务。
- 输出使用生产 JSONL 解析器和资产检查器复核，另人工核对保温杯裂缝/胶印/兔子贴纸、白色杯身/透明杯体/绿色按键/Type-C、林深主卡与雨夜子卡、同地点复用和不同地点区分。
- 后台官方技能包评测另验证上传、静态校验、候选与基线、评测门槛及激活路径；不得用强制启用跳过失败门槛。

## 结果

验收增加了内容覆盖门槛，不能只看后台解析率：七名出镜说话角色、两种杯子、插线板、毛巾、产品 Type-C/白色/绿色关键外观和运行场 4 的围裙子卡都必须保留。真实输出固化于 `backend/internal/drama/testdata/assets-skill-p0/suixingxian.jsonl`，由生产解析器与检查器执行回归。

迭代过程中，初版候选出现一条未转义引号的 JSON 行及自行补出的商品容量，已补入逐行复核；第二版结构检查通过，但漏了顾客 A/B 和合并场中的围裙换装，内容覆盖测试准确报出三个失败，未据此启用。补强覆盖规则后重新运行候选组，保留原始失败记录及旧版基线。

本地 `internal/drama`、`internal/skills` 及资产流程/技能评测应用专项通过。Windows 整包 `internal/app` 在 10 分钟总时限到期时退出，当时运行中的 Agent 测试仅执行 7 秒，不能将该全量命令计为通过；最终全量结果以发布流水线为准。

DeepSeek 调试阶段复现了旧版把两种杯子、两种货箱及顾客 B/C 误合并的问题；补强候选在第五轮连续三次收到上游 HTTP 502 后停止重试。正式 A/B 改用同一 GPT-6.1 渠道将两组从头运行，没有将不同模型结果混作对照。502 原因未由上游明确返回，不能归因于技能或将其算为质量通过。

GPT 首轮也暴露合并场的后半段漏提：旧续场只给摘要和运行场次号，模型容易误按原文场次号继续。后端资产步骤改为续场显式提供本轮完整正文和原始标题，不改变通用切场、色卡编号或分镜流程。修复后两组重新从头运行，避免将不同输入条件的结果混作对照。

进一步核对发现仅写“本轮正文范围”仍会让模型漏掉后文才出现的稳定接口特征；最终续场明确区分出场范围与外观取证范围。候选补充首次建卡汇总全篇明示事实、中文与英文同时保留细节、palette_hint 仅写中文色名等约束。恢复检查点同时核对完整正文，拒绝正文变更或缺少范围的旧检查点。
