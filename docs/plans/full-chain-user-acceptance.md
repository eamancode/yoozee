# 八场剧本真实前端全链路验收

使用用户提供的八场「随行鲜」剧本，通过真实前端创建项目，使用站内已配置的文本、图片和视频模型。原稿及运行凭据保存在本机私有验收归档，本文不发布完整原稿或凭据。

## 当前真实结果

- 旧标签页仍加载旧入口文件，旧建项弹窗已选择写实 CG 后被新接口拒绝。对照当前页面 script 与服务器首页入口文件确定为旧客户端合同不匹配；保存表单后刷新，进入新建项页面，已正常建项。
- 八场原稿 6676 个字符完整保存，读取后逐字比对一致。正确识别为一集剧本；当前切场规则合并连续同地点的第四、第五场，生产流程为七场，原场次头和正文均保留。
- 写实 CG、9:16、每段 15 秒，项目创建约 1 秒。导演风格分析和场次色卡成功；资产提取在完成前三场后遇到上游 HTTP 502，从第四场续跑仍遇到 502，停止同线路重试。
- GPT 线路原 OpenRouter 协议没有进入标准文本流式分支，长请求遇到 524；后台将同一模型切到标准 Chat Completions，真实短连接测试 38.08 秒通过，能力上限和价格保持原值。长任务已完成前四场，随后遇到供应商账号并发限制，冷却后从第五场成功续跑；未从头重做。
- 资产提取共保留五场结果，供应商账号并发限制连续拒绝后三场中的后续请求，备用文本型号也被相同限制拒绝；其他线路分别返回 502 和 401。已停止同类重试，完整资产和 82 节自动分镜未判通过。
- 使用已生成的阿婆描述，通过前端新建角色卡并生成三视图，图片模型约 29 秒完成；另手动保存原第一场开头的 15 秒样片分镜，约 39 秒生成开场分镜图。两项均为站内真实图片模型结果，人工补全与自动提取通过分开记录。
- 视频本轮两次提交：XB 返回 503「没有可用通道」，MJ-30 已受理并进入上游生成。此前恢复验收成功线路实际为 MJ-30；XB 曾在 10 秒能力检查时被拒绝。XB 的 4/30 秒枚举配置保持原值，不依据展示说明放宽模型合同。连同历史一次共用完三次视频请求额度，后续只查询已有任务。

## 已定位并修复的产品问题

- 续跑先继承旧结果，却只在第一条新结果成功后落检查点；续跑首轮失败时结果为空，页面失去继续入口。后端改为调用模型前保存继承进度；前端对当前已中断的运行沿同项目、同运行、同步骤和同单元查找有效检查点，防循环和跨项目引用。
- 资产断点续跑增加文本模型选择，可换站内模型继续剩余场次，无需重跑已完成部分。
- 流水线状态由项目布局共享订阅，阶段变动后刷新项目数据，避免章节页仍显示「风格未锁定」而禁用色卡操作；概览当前任务以真实流水线阶段为准。
- 自动项目名去除场次后的竖线及日夜/内外后缀。
- 后续定位：手动绑定色卡错误使用普通参考角色，也会写进段的构图参考。改为 `style` 引用，不写入内容参考；参考图构建器按资产分类排除色卡，避免旧的普通引用把色卡混入分镜图或扰乱图片编号。专项测试覆盖普通误绑与规范色卡用途；待本轮发布。
