# 短剧工作流优化需求说明

状态：已确认并进入实施与回归，发布结果以验收报告为准。

## 1. 目标与范围

本次处理四项需求：预演改为可选辅助环节；同场景白模参考进入对应镜头的分镜图附件且缺失不阻塞视频；修复历史失败链占用章节；文本、图片和视频选模默认使用当前用户最近使用的可用模型，文本首次默认 `gpt-6.1-sol`。

保留刚还原的台词、画外与旁白流程，以及现有 15/30 秒时长适配、权限、报价、计费、防重复提交和取消保护。不调用真实视频模型，不自动重试历史失败任务，不自动停止现有任务，不重写历史剧本或已有视频。

## 2. 现状与排查结论

| 项目 | 当前实现 | 问题 |
| --- | --- | --- |
| 预演闸门 | `auto` 根据生成模式启用；启用时必须有选中且有效的动作预演 | 用户没有生成预演时可能无法提交视频 |
| 白模衔接 | 同场景后一组要求前组可用视频、末帧、登记绑定及参考上传 | 缺图或准备失败会阻塞视频；图片主要在资产页，分镜图附件不可直接查看 |
| 图 2 提示 | 创建链时，将 queued、running 和 failed 都计入章节占用 | 历史失败链也会挡住新请求；只显示提示，缺少直接处理入口 |
| 默认模型 | 分散使用全局默认、项目默认、弹窗状态、单镜头会话缓存或历史产物 | 同一用户在不同环节需要重复选择，默认来源不一致 |

## 3. 术语

- 镜头组：一次提交视频生成的小节，可包含多个镜头。
- 连续链：叙事顺序相邻且属于同一场景的一组镜头组。
- 白模参考：前一镜头组视频片末截取的图片，用于下一组起始站位参考，不等同于动作预演。
- 分镜图附件：分镜制作页中，对应镜头组的“分镜图”产物与历史列表。
- 最近使用：当前用户最近一次成功提交并被系统接受的生成任务所选模型，不要求该任务最终生成成功。

## 4. 预演可选

### 4.1 业务规则

1. 分镜图、动作预演和镜头视频是可以分别使用的能力。
2. 用户可以直接生成视频，无须先生成分镜图或动作预演。
3. 未生成、生成中、生成失败、已过期或未选中预演产物，均不作为禁止提交视频的理由。
4. 历史项目的预演闸门配置不得继续隐式强制用户先生成预演。
5. 用户可以主动生成和查看预演；视频生成不自动附带额外的预演生成任务。
6. 没有预演时，仍使用原镜头正文、原参考图和所选模型生成，不替换或清空镜头内容。

### 4.2 页面与服务端

- 将“预演闸门”的硬性前置语义调整为“动作预演（可选）”，默认可跳过。
- 视频生成区明确提示：“分镜图与动作预演均为可选，可直接生成视频。”
- 不因缺少预演而禁用视频按钮；普通提交、同场景连续链和 Agent 业务入口遵循同一规则。
- 去除仅由缺少预演触发的 `previz_required` 拦截。权限、模型能力、必填正文、正常资源输入及余额校验继续有效。

## 5. 白模参考的存放与展示

### 5.1 归属约定

采用以下方案：A 的白模末帧作为 B 的起始站位参考，放入 **B 所属场次、B 镜头组的分镜图附件**。同时记录来源是 A，保留已有分镜参考资产和镜头绑定。引用同一资源，不重复保存物理图片。

### 5.2 展示规则

1. 在对应镜头的“分镜图”中可预览、放大、下载，并能在历史中找到。
2. 标识为“上一组白模站位参考”，显示来源镜头组、来源视频及截帧时间（可取得时）。
3. 不覆盖或删除用户已有分镜图；已有选中分镜图保持选中，白模图作为独立附件可查看。
4. 重复准备、重复提交或显式重试，不重复增加同源附件、资产或绑定。
5. 旧版本/旧来源视频的白模图保留来源信息，不静默作为当前参考。
6. 本期先保证新增白模图自动归档；现有已登记且有效的参考在读取或复用时可以补齐附件，不为补附件调用模型或重新生成视频。

## 6. 白模缺失时的生成规则

### 6.1 连续链

- 同场景链仍按叙事顺序执行；当前组视频生成成功后，下一组尝试复用或截取末帧、保存附件并上传。
- 成功取得并上传白模参考时，追加到下一组原参考图片之后，提示词开头使用实际上传图片的编号。
- 白模参考不存在、截帧失败、可选参考登记失败、可选图片上传失败、模型不支持额外参考图或额外图片超出容量时，本组跳过白模参考并继续视频生成。
- 跳过时保留原有人物、场景、道具与风格参考；不添加不存在图片的站位提醒，不自动删除原参考图来腾出名额。
- 原参考图片本身无效、上传失败或超过模型限制，仍按正常输入错误处理，不伪装成“白模已跳过”继续。
- 上一组视频仍在生成时，连续链后组仍等待；上一组视频任务本身失败时保留现有暂停与显式续跑规则。这与“白模准备失败不阻塞”分开处理。

### 6.2 单组提交

单独提交某镜头组时，上一组没有视频、没有白模或历史视频没有白模结束段，也允许按本组正文和原参考图生成；有可用参考时尽量使用，无可用参考时提示“本次未使用上一组白模站位参考”。不要求用户先补生成上一组。

### 6.3 提示与重试

- 白模跳过显示非阻塞说明和原因，不能把整条视频链标成失败。
- 一次提交中的可选白模准备失败后不无限重试；保存跳过状态，防止调度重复尝试。
- 用户后续可主动准备或更新白模附件，但不自动重试历史失败的视频任务。
- 已保存白模图片但上传失败时，图片仍可查看，本次视频可以不用该图。

### 6.4 提示词及报价

顺序仍为“实际存在的站位参考提醒 → 当前镜头组正文 → 符合同场景后续条件时的片末结束段”。没有实际白模输入时省略开头提醒，其余正文完整保留。

片末结束段沿用已确认原文：

> 【本镜最后阶段】视频最后1秒，硬切至斜向下45度俯视的大全景机位，画面同时切换为无贴图的哑光白色三维白模。完整呈现场景空间布局、主要道具及本小节最后一个镜头结束时仍在场景内人物的全身。保持人物原有站位、朝向、姿态及彼此距离，保持场景结构和道具位置不变。锁定机位与构图，持续1秒直至视频结束；人物仅有轻微呼吸起伏和身体自然晃动，双脚保持原位。保留柔和阴影，使人物轮廓、遮挡关系和空间层次清晰可辨。

最终报价、参考数量、操作类型及提交参数按本次实际输入统一计算；跳过白模不得造成重复计费，或静默超过已授权预算。若最终输入对应更高价格，仍遵守已有预算确认规则。

## 7. 图 2：连续链占用修复

| 已有链状态 | 新请求行为 |
| --- | --- |
| 同一个提交标识 | 幂等返回原链，不重复创建或扣费 |
| queued / running | 保留执行中防并发保护，直接展示关联链及处理入口 |
| failed | 不再作为章节占用；用户可以显式续跑，也可以提交新请求 |
| cancelled / succeeded | 不阻止新请求；历史保留 |

补充要求：

- 显式续跑旧失败链前，重新检查本章节是否已有执行中链，防止绕过互斥。
- 真正冲突时展示正在运行的链、进度及涉及镜头，提供“查看生成链”和“停止后续生成”入口，不只弹出不可操作的提示。
- 不自动停止已有链，不自动续跑旧失败链，不自动重复用户的新提交。
- 本期修复历史失败占用与冲突可处理性，不扩展同章节同时运行多条链的范围。

## 8. 最近模型记忆与默认选择

### 8.1 记忆规则

1. 文本、图片、视频三类分别记忆，以当前登录用户为范围。
2. 在生成任务成功提交并被系统接受后记录；只打开弹窗、仅报价、取消选择或提交前校验失败不覆盖最近记录。
3. 跨章节、跨项目和页面刷新后仍可使用；退出登录、切换账号后隔离。
4. 保存完整的可执行模型选择标识，包含对应渠道或逻辑模型身份，不能只保存可能重名的展示名。
5. 只记忆模型选择，不保存 API Key、Cookie、媒体大对象或临时上传地址。
6. 自动链式调用不应把用户最近选择改成服务端内部回退模型；记录用户实际提交选择。

### 8.2 默认优先级

| 能力 | 打开或重新进入选模界面时的优先级 |
| --- | --- |
| 文本 | 最近使用且仍可用的文本模型 → 可用的 `gpt-6.1-sol` → 可用的现有配置默认 → 当前可用候选 |
| 图片 | 最近使用且适配当前任务的图片模型 → 可用的项目默认 → 可用的全局默认 → 当前可用候选 |
| 视频 | 最近使用且适配当前任务的视频模型 → 可用且同项目模型族的项目默认 → 当前可用的同族候选 |

“适配当前任务”包含模型是否启用、权限、时长、项目模型族、参考图片数量及操作类型等校验。旧的单镜头会话记录、历史产物模型不能无条件覆盖用户更新的最近使用模型；历史产物的原生成模型仍作为产物信息展示。

已打开的界面中，用户当前手动选择保持稳定，不因其他环节更新最近记录而突然切换。再次进入或打开面板时才按最新记录初始化。

### 8.3 文本默认与失效回退

- 没有最近文本记录时，优先选目录中真实可用的 `gpt-6.1-sol`，而非仅将占位文字改成该名称。
- 同名模型有多个渠道时，保存实际选中的渠道标识；首次选择按现有可用渠道规则解析。
- 最近模型下线、无权限或不适配本任务时，按优先级选择可用模型，并显示回退原因及当前模型。
- `gpt-6.1-sol` 不在可用目录时，提示不可用并使用可用回退，不创建虚假模型条目。
- 没有可用候选时明确提示配置模型，不以空模型提交。
- 仅调整短剧工作流，不改变自由画布和其他产品的默认模型，也不改变刚还原的声音流程。

### 8.4 覆盖入口

| 环节 | 涉及能力 |
| --- | --- |
| 剧本优化、改编及节奏调整 | 文本；启用后续图片任务时涉及图片 |
| 导演风格分析与风格封面 | 文本、图片 |
| 场次色卡、资产提取与资产出图 | 文本、图片 |
| 生成分段、重写小节与戏类调整 | 文本 |
| 人物主卡、子卡、场景、道具、图片失败恢复 | 图片 |
| 分镜图、动作预演 | 图片 |
| 单组视频及同场景连续生成 | 视频 |
| 其他短剧步骤中的模型选择 | 按对应文本/图片/视频能力统一处理 |

## 9. 交互与状态要求

- 白模属于辅助参考，界面同时显示“是否使用”和“跳过原因”，不出现“未传图却声称已使用”的状态。
- 分镜图附件区分普通分镜图与白模站位参考，用户能辨认来源。
- 运行中链冲突可以定位与处理；历史失败可保留查看和显式重试入口。
- 默认模型在界面中的显示值、报价使用值和实际提交值一致。
- 原内容时长与生成档位分开显示，沿用既有 15/30 秒适配，不因换默认模型修改剧本或镜头内容。

## 11. 实施与回归顺序

1. 修复失败链占用与续跑互斥，补充幂等和冲突展示回归。
2. 去除预演硬前置，覆盖普通入口、连续链及 Agent 路径。
3. 完成白模附件化、可选降级、来源记录和防重复。
4. 统一用户最近模型记忆及各处默认初始化。
5. 使用本地模拟上游验证“报价 → 原参考/白模参考准备 → 视频提交”，补充缺图、失败降级、取消和防重复回归；不调用真实视频模型。
6. 完成前后端必要回归和真实路由只读验收，形成结果清单；通过后推送并部署。
