# 同场景衔接修复、分镜参考资产与统一风格中心需求说明

状态：用户已确认，按更新后的结束段实施。实现、自动回归、部署与真实模型视觉验收分别记录，不以代码存在代替上线或视觉通过。

## 1. 需求复述与目标

本次优化包含两条主线：

1. 修复同场景视频衔接。针对用户反馈的最新两条视频，查清后一镜头组为何未携带前一组的白模末帧；让连续生成真正按视频完成、截帧、资产登记、参考准备、下一组提交的顺序自动执行。截帧作为项目资产管理中的新类型“分镜参考”，自动绑定到使用它的下一镜头组，用户可以查看和追溯。
2. 统一到用户截图中的风格中心。该中心具有“系统风格、我的风格、收藏、最近使用”等入口。用户自行创建、复制修改及项目导演生成的个人风格统一进入这里的“我的风格”，字段、预览、编辑和应用方式与系统风格对齐。导演风格完成后自动生成一张实际风格图作为封面，用户可查看。个人风格仅创建人可见，不进入全平台系统风格。

不再以后台另一套导演风格库代替截图中的“我的风格”，也不能仅把另一套库的入口改名来算完成统一。

## 3. 同场景生成规则

### 3.1 场景归属与链边界

- 按当前章节中镜头组的实际叙事顺序、有效场景归属形成连续链，不按视频生成时间或页面排序判断。
- 同一场景但中间隔着其他场景的镜头组不能跨越连接。
- 场景改变即结束当前链；新场景第一组不继承上一场景的末帧。
- 场景归属缺失或不明确时，显示需补齐的原因，不能凭名称相似或空值相等建立依赖。
- 链内第一组直接提交；第二组及后续组必须等待上一组视频成功且文件可读、末帧已保存并完成所需参考准备后才提交。
- 除链内最后一组外，其余各组在提交提示词末尾自动追加结束段；最后一组仍使用上一组末帧，但不追加结束段。
- 没有同场景前后续组的独立镜头组不自动追加结束段，也不继承其他场景的图片。

### 3.2 统一入口的建议默认行为

以下是本需求草案建议采用的入口规则，用于避免普通按钮绕过衔接：

- “同场景连续生成”一次启动当前连续场景链，后台自动完成后续步骤，不要求逐组点击。
- 单独生成链内第二组或后续组时，同样检查并准备有效前序末帧，不得静默按普通无站位参考的视频提交。
- 单组按钮不擅自启动未被用户选择的前序或后续收费视频任务。缺少有效前序视频时，提示先生成前序组，或由用户显式发起整链生成。
- 不同入口复用同一后端依赖校验、参考组装和提示词提交规则。页面隐藏按钮不能代替服务端校验。
- 前序已有视频如未按本需求生成结束段，应如实标注“历史视频未保证含白模结束段”，不将普通末帧宣称为白模参考；给出重新生成前序组或发起新链的入口，不自动调用视频模型。

这一规则不增加白模画面识别或人工逐帧确认，只依据任务生成参数和来源记录判断是否执行过规定的结束段。

### 3.3 结束段原文

符合条件时，在后端提交生成任务时自动追加以下原文：

> 【本镜最后阶段】视频最后1秒，硬切至斜向下45度俯视的大全景机位，画面同时切换为无贴图的哑光白色三维白模。完整呈现场景空间布局、主要道具及本小节最后一个镜头结束时仍在场景内人物的全身。保持人物原有站位、朝向、姿态及彼此距离，保持场景结构和道具位置不变。锁定机位与构图，持续1秒直至视频结束；人物仅有轻微呼吸起伏和身体自然晃动，双脚保持原位。保留柔和阴影，使人物轮廓、遮挡关系和空间层次清晰可辨。

定格指机位与构图固定，人物仍有上述轻微动态。最后 1 秒包含在本次视频总时长中，不额外延长。白模结束段不覆盖或删减原镜头正文。

人物范围以本小节最后一个镜头结束时的剧情在场状态为准：已离场的人物不补回，仍在场但处于画外的人物应纳入大全景；若人物已全部离场，则呈现空场景白模。不能按整场曾出现的人物名单补齐，也不能只按最后一镜画面内可见人物裁减。

### 3.4 末帧提取与真实传递

1. 确认前序任务成功，并确认对应选用的视频版本和文件可读取。
2. 截取最后一帧；精确末帧不可读时，使用最接近结束时间的可读取帧，记录实际时间位置和降级情况。
3. 保存图片资源并登记“分镜参考”资产，关联来源镜头组、镜头版本、视频任务和视频资源。
4. 将该资产绑定为下一镜头组的“上一组末帧 / 站位参考”。
5. 保留下一组原有的人物、场景、风格及其他参考图片，新增末帧，不能用末帧替换它们。
6. 按当前所选模型的协议，上传图片或准备模型可读取的资源输入。协议直接接收 URL 时，核实提交输入确实指向该图片；不能仅以站内绑定成功当作已传递。
7. 参考输入准备完成后，计算实际图片引用标识，组装最终提示词并提交下一组。

不把站位参考强制当作锁定首帧。模型不支持所需参考图片，或保留原图片后数量超限时，暂停并明确提示处理，不自动丢掉站位图或其他原参考图。

### 3.5 下一组开头提醒与提示词顺序

使用前一组末帧的镜头组，开头自动加入：

> 【站位参考】参考图片「{站位参考图标识}」为上一镜头组的片末白模画面。请以该图中的人物位置、朝向、彼此距离，以及场景结构和道具位置，作为本镜起始状态的空间参考；后续动作与运镜按照本镜正文执行。人物外观、服装、场景材质、色彩和光照遵循本镜正文及其他对应参考图，白模材质和参考图机位不作为本镜的画面风格或起始机位要求。

`{站位参考图标识}` 必须替换为当前模型可以对应到实际提交图片的标识，不使用虚构编号或上次任务的过期编号。

最终顺序固定为：站位参考提醒（适用时）→ 当前镜头组原有提示词 → 结束段（适用时）。提交前重新读取镜头顺序、场景归属、内容版本和模型能力；自动提醒与结束段不反复写回正文造成叠加。

### 3.6 A → B → C 执行表

| 镜头组 | 提交前提 | 开头提醒 | 结束段 | 参考资产 |
| --- | --- | --- | --- | --- |
| A | 可直接提交 | 无 | 有 | 不继承外部场景末帧 |
| B | A 成功、视频可读、截帧及参考准备完成 | 引用 A 实际末帧 | 有 | 来源 A，使用组 B |
| C | B 成功、视频可读、截帧及参考准备完成 | 引用 B 实际末帧 | 无 | 来源 B，使用组 C |

### 3.7 失败、续跑、取消与幂等

- 前序未完成时，后续组显示“等待上一组”，不提前提交。
- 视频、截帧、资产登记、绑定、上传和提交分别记录状态；任一步失败暂停依赖它的后续组，显示具体原因与重试入口。
- 重试从失败步骤继续，复用成功且仍有效的视频、截帧、资产、绑定和协议上传结果。
- 重复点击、超时重发、任务重试、服务重启均不得重复创建收费子任务、参考资产或绑定，不重复追加提醒、结束段和同一张站位图。
- 来源视频、镜头内容、场景、叙事顺序或模型改变时，重新判断依赖；旧参考保留为历史记录，不能继续标为当前有效参考。
- 用户取消后，不再自动提交未开始的后续组。已提交任务及成功产物保留；已取消链不因迟到回调重新启动。

## 4. 资产管理新增“分镜参考”类型

### 4.1 类型与可见性

- 项目资产管理增加独立业务类型“分镜参考”，媒体格式仍为图片。
- 白模末帧保存后自动进入该类型，不混入人物、场景、道具分类，不被普通资产提取或批量出图当作待制作资产。
- 卡片显示缩略图、名称、来源镜头组、使用镜头组、来源视频版本、生成时间和当前/历史状态；可打开完整预览、跳转来源视频及使用它的镜头组。
- 建议名称为“第 N 场 · A组末帧 → B组站位参考”，实际使用项目已有编号和名称。
- 不把图像识别或白模质量检测作为入库条件；“白模末帧”标记表达生成指令与来源，不冒充已完成视觉质量审核。

### 4.2 对应镜头的绑定口径

- A 的末帧记录“来源为 A”，自动绑定到下一组 B 的参考区；A 可查看自己产出的末帧，但不将该图自动当作 A 的输入参考。
- 分镜制作中的 B 显示“上一组末帧 / 站位参考”，提供预览与来源追溯，提交时实际使用这张图。
- 资产与镜头绑定必须持久化，刷新页面或服务重启后可恢复。手动把同一资产绑定到同一组不重复叠加。
- 用户解除或替换参考后，原生成链的待提交步骤必须重新校验，不得悄悄继续使用已失效的计划。
- 有视频链、镜头或历史任务引用的资源不能被无提示物理删除；使用现有资源引用保护和删除反馈。

### 4.3 最小来源记录

持久化语义至少包括：项目、章节、场景、来源镜头组及版本、来源视频任务及资源、截帧资源、实际截帧位置、消费镜头组及版本、生成链/步骤、模型引用标识及协议准备状态。具体字段名与表结构由实施设计确定，不在需求阶段锁死。

## 5. 风格中心统一

### 5.1 唯一产品入口

- 以用户截图的“风格中心”为准，保留系统风格、我的风格、收藏、最近使用、搜索、分类、预览、复制、应用及当前选中状态。
- 系统预置留在“系统风格”；个人创建、从系统复制修改、以及项目导演生成的风格进入创建人的“我的风格”。
- 建项、项目设置、导演结果保存和画布选用同一套个人风格档案。不能出现保存成功却在“我的风格”中看不到的平行库。
- 我的风格列表、详情、封面、编辑、删除和选用均在服务端校验创建人。收藏、最近使用和搜索不能泄露他人的个人风格。

### 5.2 字段与系统风格对齐

| 字段组 | 对齐内容 |
| --- | --- |
| 基本信息 | 名称、简介、标签、封面、分类展示 |
| 风格组合 | 题材世界、叙事气质、视觉媒介、角色造型 |
| 视觉规范 | 完整正向 Prompt、负向 Prompt、使用边界 |
| 执行配置 | 现有执行资产和执行策略；存在真实绑定时保留，不要求模型编造 LoRA、资源 ID、渠道或参数 |
| 系统记录 | 创建人、来源项目、来源系统风格（如有）、版本及更新时间；不作为模型自由输出内容 |

个人风格使用系统风格的完整规范结构，不能只保存名称、导演短描述或主色卡。依据当前系统风格编译器，完整章节包括：

1. 风格组合。
2. 项目定位。
3. 题材世界观。
4. 叙事气质。
5. 视觉媒介。
6. 角色设计系统。
7. 项目色彩与光影。
8. 服饰、材质与场景。
9. 影像与动态基线。
10. 资产一致性。
11. 全局禁用。
12. 使用边界。

导演新增的媒介、美术、灯光政策、镜头语言、调色、禁用项及主基调色卡，应按语义整合到对应章节并保留结构化数据供后续流程使用。项目类型与风格组合不得互相冲突，同一规范内不能出现两套相互矛盾的要求。

### 5.3 项目导演结果的保存与复用

建议默认：导演风格分析完成并保存后，自动建立或更新该项目关联的一条“我的风格”，同时保存项目当时应用的快照，并启动一次封面图片生成。

- 同一任务重复收尾不得创建重复个人风格或重复封面任务；同项目重新分析形成可追溯的新版本，不刷出大量同名卡。
- 用户手动编辑过的个人档案不能被迟到任务覆盖；发生并发修改时给出保留版本和处理入口。
- 用户能在“我的风格”预览、编辑、复制及应用到其他项目，能力与系统风格选用一致。
- 修改个人风格不自动改写其他项目已应用的历史快照，原生成结果的风格来源可追溯。
- 既有另一套库中的个人导演风格，按原创建人归并到“我的风格”，保留已有内容、来源与项目关联，幂等迁移、不重复卡、不改成公共风格。原本就属于公共预置的条目保持公共属性。

### 5.4 自动生成风格封面

- 生成一张实际图片，用于展示该导演风格的媒介、人物造型语言、材质、光影和色彩气质；不得仅用代码色卡、白模图或无关默认图片充当生成成功的风格封面。
- 封面提示词从已保存的完整风格规范与项目内容提炼，生成时使用文本中的明确风格约束，避免封面与规范媒介不一致。
- 建议优先使用项目默认图片模型，未配置时使用有效的全局默认图片模型；均不可用时保留风格文本，显示“封面待生成”及配置/重试入口。
- 封面经历待生成、生成中、成功、失败等状态。成功后持久化为受权限保护的图片资源，并关联具体风格版本；页面刷新仍可查看。
- 封面生成失败不回滚已保存的导演风格，不重复跑文本分析；用户可单独重试封面。存在旧成功封面时保留旧图并明确显示新版封面状态，禁止用旧任务回调覆盖新封面。
- “我的风格”卡片、详情和项目导演结果区均可查看封面，支持放大预览；提供重新生成入口并遵守已有任务、费用和防重复提交规则。
- 封面默认用于风格展示，不自动污染人物/场景/道具资产，也不未经明确配置加入每个镜头的模型参考图。

## 6. 故障排查与修复交付要求

实施时先定位用户所指项目内最新两条视频，不把全平台最新任务当作样本。对照任务和请求证据，至少回答：

1. 两组的实际叙事顺序、场景归属、镜头版本是否一致，是否应当在同一链内？
2. 分别经由普通生成、重新生成、批量入口还是连续链创建？后一组是否具有有效的前序依赖？
3. 前一组最终提交是否包含规定结束段？后一组是否在前序视频可读后才开始？
4. 是否成功截帧、保存为资源及分镜参考资产，并绑定到后一组？每一步是否有明确状态？
5. 模型适配、上传结果和最终请求是否实际包含该图片？开头引用标识是否对应真实图片位置？
6. 是否发生参考数量超限、模型能力不支持、协议忽略输入、来源/版本失效、重试或入口绕过？失败是否被吞掉而继续提交？

最终输出“原因、证据、修复、回归结果、仍待真实成片确认的部分”。只能通过任务链路和实际输入证明参考图已传递，不能仅凭前端出现缩略图或视频生成成功推断。

历史生成视频无法通过补绑定图片改变内容；修复可补登记有依据的历史参考资产，但不宣称历史视频已重新衔接，不自动付费重生成历史视频。

## 7. 验收标准

| 编号 | 验收场景 | 预期结果 |
| --- | --- | --- |
| C01 | A/B/C 连续同场景 | A/B 追加结束段，C 不追加；B 使用 A 末帧，C 使用 B 末帧 |
| C02 | A 尚未成功或文件不可读 | B/C 等待，不提前提交 |
| C03 | A 完成 | 自动截帧、登记资产、绑定 B、准备参考输入，再提交 B |
| C04 | B 完成 | 同样准备 B 的末帧后提交 C，无需手动逐组触发 |
| C05 | 场景变化或单独一组 | 不跨场景传图；独立单组不追加结束段 |
| C06 | 原参考图存在 | 原人物、场景、风格等参考保留，末帧新增为站位参考，引用标识一致 |
| C07 | 模型不支持或参考数量超限 | 暂停并说明原因，不忽略站位参考继续生成 |
| C08 | 截帧、登记、绑定或上传失败 | 暂停后续；从失败步骤重试，复用有效成功结果 |
| C09 | 重复点击、失败重试或服务重启 | 不重复子任务、资产、绑定、参考图或提示词段落 |
| C10 | 用户取消 | 未开始的后续组不再自动提交，迟到回调不重启链 |
| C11 | 普通按钮单独生成后续组 | 执行相同前序参考校验，缺前序时明确提示，不静默绕过 |
| C12 | 来源视频或镜头内容变化 | 旧参考标历史/失效，重新准备当前有效依赖 |
| C13 | 小节末有人离场或仍在画外 | 只呈现最后一镜结束时仍在场的人物全身，不补回已离场人物；仍在场的画外人物纳入大全景 |
| C14 | 小节末人物全部离场 | 呈现空场景白模，保留空间布局及主要道具，不重新添加人物 |
| A01 | 打开项目资产管理 | 可筛选“分镜参考”，预览、来源与使用镜头信息完整 |
| A02 | 打开 B 的分镜制作 | 可见来源 A 的站位参考且实际提交包含该资源；刷新不丢失 |
| S01 | 生成项目导演风格 | 自动进入创建人的“我的风格”，不进入系统风格或另一套个人库 |
| S02 | 个人风格详情/编辑/应用 | 与系统风格字段和完整规范对齐，含叙事气质、影像与动态基线及使用边界 |
| S03 | 导演风格封面成功 | 展示实际生成的风格图片，卡片和详情可放大查看，刷新仍在 |
| S04 | 封面失败或图片模型未配置 | 文本风格已保存，明确待生成/失败，支持独立重试，不重跑导演分析 |
| S05 | 跨账号读取或猜测 ID | 我的风格及封面均不可被其他用户读取，公共系统风格仍可正常浏览 |
| S06 | 重复收尾、重新分析及并发编辑 | 不重复卡片或收费任务；版本可追溯，旧回调不覆盖新版本 |
| S07 | 既有导演个人风格归并 | 归入原创建人的“我的风格”，内容和项目快照不丢失、不公开 |

自动回归和模拟模型可以验证时序、输入、权限及幂等；不能替代真实视频对白模构图、小节结束时仍在场人物的全身覆盖和站位保持的视觉验收。真实视频模型调用继续暂停，后续另行安排视觉验收。

## 8. 建议实施顺序

1. P0：定位最新两条视频的实际任务证据，修复入口绕过、依赖或协议传图问题，并补针对性回归。
2. P0：分镜参考资产化及下一组绑定，覆盖失败续跑、取消、重复提交和资源保护。
3. P0：统一个人风格到截图中的“我的风格”，对齐完整系统字段及创建人权限，处理既有个人记录归并。
4. P1：导演风格封面自动生成、预览、失败重试和版本保护。
5. 回归通过后再按确认范围发布，核实实际运行版本、技能包版本、登录态、任务与资源访问。代码通过、技能启用、生产部署、真实语义验收分别记录，不互相替代。

## 9. 本草案明确的建议默认口径

- 普通单组入口也检查同场景前序依赖，但不自动增加用户未选择的视频收费任务。
- 白模末帧来源属于上一组，自动输入绑定属于下一组。
- 项目导演结果默认自动保存到“我的风格”；同项目关联档案版本更新，不按任务无限新增卡片。
- 封面为单张实际生成的风格图；失败保留文本风格，可单独重试。
- 以上建议随本需求文档一并确认；本轮不据此自动启动实现、部署或模型调用。
